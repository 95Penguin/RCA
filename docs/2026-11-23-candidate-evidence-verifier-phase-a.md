# Candidate Evidence Verifier：Phase A 可行性实验

日期：2026-11-23

## 目的

验证 `Forecast-then-Verify` 的关键前提：在冻结正式版 LTFP 的故障预测和根因排序后，一个只查看 Top-3 候选历史证据的轻量验证器，能否稳定纠正 LTFP 的根因排序，而不破坏原本正确的结果。

本阶段只使用已有五分钟 panel 中可因果获得的 Metric/Log/Trace 汇总特征，不解析原始请求级 Trace 和原始日志。只有这个低成本筛选稳定为正，才值得实现昂贵的原始证据检索器。

## 实验设计

- Scout：正式比较实验中的 LTFP 五折 checkpoint，完全冻结；测试预测与正式 `predictions.jsonl` 逐项校验。
- 候选：LTFP 根因分数的 Top-3 服务。
- Evidence：仅使用输入窗口内的信息，包括指标相对训练期正常基线的偏离、指标动态、观测覆盖率、Trace/Log/入口统计及候选相对系统的偏离。
- Verifier：所有候选共享同一个小型证据编码器，输出有界残差；只重排 Top-3，不改变候选集合。
- 保护机制：残差强度 `rho` 只在 validation 上从 `{0, 0.25, 0.5, 1, 2, 4}` 选择，允许严格选择 `rho=0`，即完全保持 LTFP。
- 预测任务：故障预测支路完全冻结，所以 AP/F1 与正式 LTFP 严格相同。
- 评价：外层五折 test 只评估一次；同时报告窗口级和事件级 RCA 指标。

### 重要修正

最初版本把 Scout 分数和候选位置输入 Verifier，并以候选位置为监督。该设计无效：外层训练折上的 Scout 输出是 in-sample 预测，真实根因几乎总在第 1 位，Verifier 会学成“永远相信候选 0”。

正式筛选版本因此采用 evidence-only 训练：训练时 Verifier 看不到 Scout 分数和候选位置，只能根据每个候选自身证据识别根因；Scout 分数仅在 validation/test 时作为有界残差的底座。该结构对候选顺序等变，避免“位置 0”捷径。

## 三个随机种子的结果

随机种子只影响 Verifier 初始化和训练；数据划分、正式 LTFP checkpoint、候选和测试集均不变。

## 对 seed 42 正结果的拆解

seed 42 看似达到筛选线，但 OB 的事件级增益主要来自 fold 4：

|---:|---:|:---:|:---:|:---:|:---:|
| 0 | 0 | 0.840 → 0.840 | 0.847 → 0.847 | 0.722 → 0.722 | 0 / 0 |
| 1 | 0 | 0.931 → 0.931 | 0.923 → 0.923 | 0.846 → 0.846 | 0 / 0 |
| 2 | 2 | 0.956 → 0.963 | 1.000 → 1.000 | 1.000 → 1.000 | 1 / 0 |
| 3 | 4 | 0.933 → 0.931 | 0.857 → 0.857 | 0.833 → 0.833 | 0 / 0 |
| 4 | 2 | 0.821 → 0.848 | 0.767 → 0.920 | 0.600 → 0.900 | 4 / 0 |

换种子后 fold 4 的收益消失，说明它不是稳定的结构收益，而是少量边界样本与随机初始化共同造成的高方差结果。

## 结论

**Phase A 不通过。暂不实现原始日志/请求级 Trace 的完整 Forecast-then-Verify。**

原因不是“某一折下降就否定”，而是核心收益不能跨随机种子复现：同一数据和同一正式 Scout 下，OB 从 `+0.0307 Event MRR` 变成 `-0.0125` 或 `0`；TT 的 Event MRR 在三个种子下均为 `0` 增益。选择最好种子会构成明显的结果挑选。

这个实验仍给出了两个有用边界：

1. Top-3 候选覆盖率已经较高，单纯扩大候选或换一个候选排序头不是主要突破口。
2. 当前五分钟汇总证据对少数窗口有辨别力，但错误样本太少、事件数有限，轻量神经验证器的方差大于可复现收益。

如果以后重新开启该方向，前提应是增加独立训练事件或构造严格的 inner out-of-fold Scout 预测，再判断原始证据是否值得接入；不应继续在当前结果上调隐藏维度、种子或 `rho` 网格。
