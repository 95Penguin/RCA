# CPCA 作为唯一归因头：训练期辅助损失 vs 完全去掉

日期：2026-11-24。目标：让 CPCA 成为唯一的归因模块，移除推理阶段的
source/impact 学习式根因头，同时不牺牲预测性能。

## 1. 设计

- **推理模型**：`OCSIDModel(aux_root=False)`，只输出 $p$ 与 $q_o$；
  没有 `node_logits` / `node_scores`，不产生任何根因分数；归因完全由 CPCA 给出。
- **训练阶段**：可选 `aux_root=True`，用根因标签做一个辅助排序损失，
  只正则化共享编码器；该头不参与推理，也不进入归因结果。
- 关闭辅助损失：`--no-aux-root`，训练期也完全不用根因标签。

## 2. 结果

事件级预测（seed 42，五折）：

| 设置 | 数据集 | AP | F1（验证阈值） |
|---|---|---:|---:|
| 旧版（推理含学习头） | OB | 0.9675 | 0.9081 |
| 旧版（推理含学习头） | TT | 0.8530 | 0.7636 |
| 完全去掉根因监督 | OB | 0.8997 | 0.8268 |
| 完全去掉根因监督 | TT | 0.8302 | 0.7399 |
| **训练期辅助、推理无头** | OB | **0.9675** | **0.9081** |
| **训练期辅助、推理无头** | TT | **0.8530** | **0.7636** |

折级 AP（OB）：`[0.971, 0.987, 0.982, 0.947, 0.951]`；
TT：`[0.625, 0.798, 0.963, 0.913, 0.966]`。

## 3. 解释

1. **辅助损失是正则化器，不是归因模块**：完全去掉根因监督后，OB fold 0 的 AP
   从 0.971 崩到 0.688，整体 0.9675→0.8997；TT 0.8530→0.8302。
   这说明根因排序损失在训练期帮助共享编码器学到了更有区分度的服务表示。
2. **推理阶段可以完全不要它**：训练期辅助头不参与推理；
   `aux_root=False` 的模型没有根因头，输出只有 $p$ 和 $q_o$，
   CPCA 是唯一的归因模块。
3. **两种口径都诚实**：
   - 默认：训练期辅助、推理无头 → 保留预测性能，归因唯一；
   - 严格：`--no-aux-root` → 训练期也不用根因标签，预测 AP 掉约 0.07（OB）/0.02（TT）。

## 4. 论文写法

> 推理阶段，OCSID 只输出下一分钟故障概率与 operation 风险；根因排序完全由
> CPCA 给出，模型中没有学习式根因头。训练阶段我们可选地用根因标签做一个辅助
> 排序损失来正则化共享编码器；该辅助头不参与推理，也不产生归因结果。
> 消融显示，完全去掉该辅助损失会使 OB AP 从 0.9675 降到 0.8997，
> 因此默认保留它，但明确它不是归因模块。

这样既回答了“为什么还有一个根因头”的质疑，也保持了 CPCA 的唯一归因地位。

## 5. 复现

```bash
# 默认：训练期辅助、推理无头
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/train_ocsid_joint.py \
  --dataset tt --folds 0 1 2 3 4 --epochs 30 --seed 42 \
  --output artifacts/ocsid_joint_tt_seed42_auxroot_v3.json

# 严格：训练期也不用根因标签
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/train_ocsid_joint.py \
  --dataset tt --folds 0 1 2 3 4 --epochs 30 --seed 42 --no-aux-root \
  --output artifacts/ocsid_joint_tt_seed42_noroot_v3.json
```
