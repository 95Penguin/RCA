# 完整粗细粒度模型：从头端到端训练

## 实现范围

`joint-granularity` 是单个完整模型，随机初始化、联合训练、一个完整 checkpoint 同时产生系统预测和最终 RCA 排名。没有加载旧 LTFP 权重、冻结神经网络模块、detach 任务表示、旧预测残差或旧 RCA 排名拼接。训练集正常原型是统计缓冲区，并非冻结的预训练神经网络。

继续复用 LTFP 的 TCN 和图注意力编码组件，但所有权重都参与本轮训练。完整模型参数 162,503，LTFP 对照 139,591；未声称参数量匹配。

## 算法

```text
历史 Metrics / Logs / Traces
        ↓
各模态时序编码器（全部可训练）
        ├── Metric 时序表示 + 显式正常偏差 → 服务证据 E_i
        │
        └── 模态融合 + Trace 图交互 → 关系上下文 H_i、系统上下文 g

g 查询服务证据 → 注意力选择 E_i 与偏差 → 系统故障预测

E_i + H_i + g + 显式偏差 → 最终根因服务排名
```

原始 Metric 偏差由训练折正常历史窗口的 median / MAD 计算；缺失值用 observation mask 排除，退化尺度使用标准差或 1。保留最新偏差、历史最大偏差、观测均值，共 12 维，直接输入最终两个任务头，避免只能经过编码器间接传递。

对于服务 i：

`E_i = MLP([MetricTCN_i, deviation_i])`

整体上下文和局部证据计算选择权重：

`a_i = softmax_i(q(g) · k(E_i) / sqrt(64))`

系统预测使用 `g`、加权服务证据和加权显式偏差；RCA 头使用服务证据、图后上下文、全局上下文及显式偏差。服务证据向系统汇聚，全局上下文参与最终服务排序，实现一次前向计算中的双向表示交互。这里没有循环迭代推理，也不将 RCA softmax 直接视为系统故障概率。

## 训练协议

- 从随机初始化训练 30 轮，seed 42，OB / TT 各 deployment 五折。
- 历史 5 分钟，下一分钟状态任务；输入三模态保持一致。
- AdamW lr=0.001，batch=64，所有神经网络参数参与优化。
- 总损失：系统类别加权 CE + 0.5 × 事件平衡根因排序 CE；根因损失只作用于未来故障且有根因标签的窗口。node BCE 权重为 0。
- 与 LTFP 对照同时按该协议重训，不加载以前 checkpoint。
- 两个模型均按验证 AP 选择一个完整 checkpoint，最终 AP、F1、MRR、Hit@1 全部来自同一份权重，没有拆选两个任务 checkpoint。
- 原型、特征 scaler 均只用训练折拟合。没有利用测试指标选择权重。

## 与冻结版本的区别

| 内容 | 前一阶段原型 | 当前完整模型 |
| --- | --- | --- |
| 初始化 | 历史 LTFP + 新分支 | 全部随机初始化 |
| 编码器 | 冻结 | 故障和根因损失共同更新 |
| 服务表示 | 两条独立修正路径 | 两个最终任务共享 E_i |
| 系统输出 | 旧 logit + 修正 | 当前任务头直接输出 |
| RCA 输出 | 旧排序 + 修正或冻结 | 当前最终 RCA 头直接输出 |
| checkpoint | 多阶段组合 | 一个完整模型 |

### 判断与限制

完整联合训练链路可运行，两个最终任务使用同一份模型和同一组服务证据。但首版尚未获得综合性能改善：OB AP 下降 0.092283，MRR 下降 0.009931；TT AP 下降 0.039434，MRR 上升 0.021740。不能称为已经有效的最终算法。

这不说明冻结是必需的，也不证明系统级—服务级思路不成立。它说明本轮的完整结构、0.5 根因损失权重和验证 AP 选模的组合尚未平衡好两个任务。可能的任务干扰、偏差信息捷径等解释，不能单凭这张表认定为已证明的原因。

本轮只有一个训练种子，且模型参数量不同。相同超参数是一组受控比较，不等于已为每种算法找到最佳设置。

尤其需要保留历史较强 LTFP 结果作为参考：OB AP/MRR 约 0.918803/0.878226，TT 约 0.845770/0.931667。本轮额外使用事件平衡根因损失等统一设置，不能用较低的新对照取代历史较强结果而宣称领先。完整模型目前也没有超过这些历史结果。

## 实现与复现

- `src/models/joint_granularity.py`：完整模型。
- `src/models/factory.py`：`joint-granularity` 注册与任务损失策略。
- `src/training/experiment.py`：训练折正常原型配置，标准端到端训练。
- `scripts/run_joint_granularity_experiment.py`：从头训练两种模型、记录日志与结果。
- `tests/test_joint_granularity.py`：分别验证两任务梯度进入共享编码器、图层和服务证据；联合损失能覆盖所有参数；缺失指标及 checkpoint round-trip。

全部 65 项测试通过；另已从 OB / TT 保存权重单独重建完整模型，确认单文件能同时输出有限的故障 logits 与归一化 RCA 排名。训练输出目录记录在 JSON 的每条 `output_directory` 中，当前位于 `/private/tmp/joint_granularity_*_20261118`。

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -B \
  scripts/run_joint_granularity_experiment.py \
  --datasets ob tt --folds 0 1 2 3 4 --seeds 42 --epochs 30 \
  --output-dir /private/tmp/joint_granularity_new_run
```

也可直接通过 `scripts/run_re2.py train --model joint-granularity` 训练，需提供正的 `--rank-loss-weight`。结果属于单种子初步实验，尚不构成创新性或稳定优越性的证明。
