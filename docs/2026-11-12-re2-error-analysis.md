# RE2下一分钟故障预测与定位错误分析

本报告汇总seed 42、30 epochs、deployment五折的不重叠测试预测。阈值固定为0.5，未重训、未调参。阶段指标为池化out-of-fold诊断统计，不替代主表的五折均值±标准差。

## 主要发现

1. **当前高分部分依赖故障持续性，严格首分钟证据很少。** OB只有10个可确认的正常→故障窗口，另有45个故障正例的前一业务状态不可观测；TT对应为20和44。
2. **模型普遍存在状态惯性。** OB的恢复分钟误报率为35.7%–71.4%，TT为33.3%–62.5%。因此不仅要学习「是否处于故障」，还需要学习「状态是否在变化」。
3. **LTFP仍是当前最好的完整模型平衡点。** 它在TT的稳定非故障误报率最低，事件级Hit@1为0.875；OB上事件级Hit@1为0.836；但严格首分钟样本过少，不能据此声称稳定的首次预警能力。
4. **故障类型差异很大。** OB的CPU故障对所有方法都较难；TT的disk故障中，MTG/InstantOps/Eadro的正例检出率只有4.2%/4.2%/6.2%，LTFP为58.3%。
5. **图结构本身不能简单判定为无效，问题更可能是传播与任务共享方式。** MTG的Hit@1在OB/TT仅0.418/0.391，而同样使用图注意力的LTFP达到0.836/0.875。
6. **InstantOps的遮蔽式定位具有服务偏置。** OB上productcatalogservice的平均名次为5.47，TT上ts-auth-service为10.38、ts-order-service为15.33。

## 对新方法的直接启示

- **状态/关系路径**：使用绝对遥测状态与服务图，判断下一分钟系统风险；
- **变化/局部路径（待验证）**：显式建模时序差分和短期变化，但必须先证明严格首分钟中存在可学习信号；
- **任务分工**：预测头使用全局状态+变化信息，根因头优先保留局部服务证据；
- **最小验证**：先比较Persistence、线性状态探针和状态+变化探针，再决定是否增加变化支路。

以上是seed 42下的诊断性证据，最终结论仍需多种子和消融实验验证。
