# OCSID–CPCA v3：固定方法与验证结论

> 历史hard配置；后续预指定对照支持uniform，当前默认见 [v4方法](2026-11-25-method-v4.md)。

建议冻结结构，进入结果整理和写作；剩余工作是纠正版本的多种子、必要消融和表格核对，
不继续增加网络模块。当前为开发性验证，不能说正式实验全部完成或显著领先。

## 固定四模块

1. **观测对齐与正常参考**：服务/分钟/operation对齐；识别真实入口；保留唯一入口可达的观测子树，
   丢弃不连通片段但不补造边；必要时按已知时间戳精度执行有界1ms对齐；正常参考为前10分钟。
2. **双视角编码**：各模态TCN与时序注意力、模态门控融合、服务GAT；独立operation历史的共享GRU。
3. **风险融合预测**：系统和operation风险在logit空间融合；辅助根因损失仅训练使用。
4. **业务条件结构归因**：每个时间空档只记一次；按服务local及进入该服务的边等待进行正常值替换；
   用可移除入口延迟排序；保留低流量operation，hard选择退化最大的有证据业务。

预测仍为 corrected-v2 骨干，源码和已有seed42结果冻结；归因使用 corrected-v3-paths。
模态对齐是实体与时间对齐，没有新引入可学习的对齐损失。
graph构建仍在已有预处理中完成，不宣称新增动态图或因果发现算法。

## 固定归因配置

唯一默认来源为 `src/ocsid/config.py`，审计和统一推理接口共同使用：

| 参数 | 固定值 |
|---|---|
| 入口树策略 | entry-component（唯一显式业务入口的已有连通分量） |
| 时间误差界 | 每条父子边1000us，保持入口耗时；大冲突仍拒绝 |
| 最低请求数 | 1；不将低吞吐等同于业务无证据 |
| 最大采样数 | 100/operation/分钟 |
| 恢复 | replace：直接替换正常中位数 |
| operation 聚合 | hard；soft仅作对照，τ=1 |
| 空档归属 | post：相邻child间空档只归前一个child |
| 正常参考 | fixed first10 |

底层通用树函数仍保留strict默认，便于明确比较完整树假设；正式方法入口使用上述profile。
`excess`、soft、rolling与学习排序融合不作为本轮定稿配置。

## 为什么这样改

TT缺失根因证据由两种数据处理导致：多根Trace被整条拒绝，以及慢/低流量业务被20条门槛排除。
例如一个loss case中，1453条含根因服务请求因多根被拒绝；仅提取入口连通分量后，
934条重新成为可用且包含根因服务的请求。该过程不使用根因标签选择子树。
标签仅用于事后统计覆盖，没有作为恢复边或筛选服务的输入。

请求按业务入口结束时刻分桶，而非不相关片段的最晚结束时刻。
部分观测树并不等于完整真实请求；等待归属仍是模型假设，不把恢复估计称作真实修复效果。
低样本量分位数可能不稳定，所以推理接口同时输出operation请求数、被省略span和部分请求计数。

## 单一正式评价入口

审计内部event_metrics保留历史诊断形式，可能按服务覆盖窗口取均值，不能引用为正式主表。
正式主表只使用 `ocsid evaluate`：指定预测cohort，缺失服务/窗口都计入事件均值分母。

```bash
PYTHONPATH=src .venv/bin/python -B -m ocsid attribute --dataset tt --cases all \
  --output /path/to/new-tt-v3.json
PYTHONPATH=src .venv/bin/python -B -m ocsid evaluate \
  --audit /path/to/new-tt-v3.json --forecast-cohort /path/to/prediction-tt.json \
  --method cpca --output /path/to/new-tt-v3-evaluation.json
```

本轮全量输出在 `/Users/95penguin/MyDocs/项目/NextMinuteRCA-validation-20261125/paths_v3/`。
原始全量运行以excess字段为cpca，并同时存了cpca_replace；因此本轮主数来自cpca_replace。
现在默认入口为replace，cpca字段即为相同恢复规则；已用真实case验证逐窗口分数完全一致。
