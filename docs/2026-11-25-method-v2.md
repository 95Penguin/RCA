# OCSID–CPCA corrected-v2：四模块方法

> 历史候选说明；当前固定版本见 [v3方法](2026-11-25-method-v3.md)。以下excess/soft/min20不再是默认。

本文件固定模块划分。不同层次不再交替使用三/四模块命名。
实现修正后先验证两库 seed42 五折，不根据测试集挑恢复规则或调温度。
论文数字以本轮完整输出为准，旧 v3 只用于历史回归比较。

## 模块一：多粒度对齐与正常参考（Observation Alignment & Reference）

输入 metric/log/trace；按 case、分钟、服务对齐服务面板，按入口 operation 构建延迟/
请求量序列；保留原始 Span 请求树。调用图从已有 trace 预处理中构建并固定使用对称图。
这属于时间/实体对齐，不宣称额外的可学习模态对齐损失。
正常 local、edge pre/post、entry P95 使用先前的健康 warm-up；warm-up 结束前不评估。
特征归一化仅在训练折拟合，缺失观测标记保留原始 0/1。

## 模块二：双视角时序与关系编码（Dual-View Encoding）

服务分支：各模态 TCN → 时间注意力 → 模态门控融合 → 局部服务表示；
随后用最新一分钟调用图的 GAT 传播，得到服务表示与系统池化表示。
Operation 分支：同一个 GRU 分别编码每个 operation 的五分钟序列。
corrected-v2 显式把 [B,T,O,D] 排为 [B,O,T,D]，避免混合接口历史。
此处复用 LTFP 时序/图骨干，从随机初始化训练，不能称全新骨干架构。

## 模块三：业务风险融合预测（Risk Forecasting）

系统表示输出 p_sys；operation 表示输出 q_o，默认 max 聚合为 p_op；
两个风险的 logits 线性融合，输出下一分钟概率 p。
q_o 受系统级聚合监督，当前不是独立标注的 operation 概率，不能称精确定位接口的监督头。
训练损失：系统 BCE + 0.2 operation 聚合 BCE + 0.5 正例根因辅助交叉熵。
辅助头只在 model.training=True 时计算，eval 不输出辅助根因分数。
本轮保持损失权重、网络宽度、训练轮数和主协议，不做额外测试集调参。

## 模块四：业务条件结构归因（Operation-Conditioned Attribution）

输入是当前已完成请求树与先前正常参考，而非未来 Trace 或根因标签。
每个请求的串行分解中：第一段 pre 归首个 child；中间空档只归前一个 child 的 post；
最后 post 归最后 child。每段时间仅计一次。可选 pre 规则作为敏感性分析。
并行、父子越界、多根、重复 ID 和不连通树明确拒绝，报告拒绝与覆盖率。
local 是按该归属规则留下的时间，不等于直接测得的 CPU 计算耗时。

恢复服务 i：恢复其 local 及进入该服务的调用边等待。主候选使用 min(当前值,正常中位数)，
即只移除超额成本；replace 模式只修正守恒、直接替换正常值，作为恢复规则对照。
请求分数 Δ_i=max(D-D_after_i,0)，operation 内责任 r_i=sum(Δ_i)/sum(D)。
多个 operation 用入口当前 P95/正常 P95 的 softmax 聚合，温度预先固定 1，hard 为对照。
预测 q_o 不作归因权重；rolling 参考与学习式排序融合不进入主方法。

串行加法结构下，可直接累加同一服务的组件收益；与逐服务树重放代数等价，
复杂度由 O(服务数×span数) 降至 O(span数)。测试同时保留递归 replay 作参照。
因此不能把通用并行关键路径发现作为当前贡献；核心是成本归属及结构恢复估计。

## 两任务如何衔接

`ocsid.inference.predict_and_attribute` 提供单窗口统一接口：
模块一/二/三给出风险；超过验证集阈值后，模块四给出根因排名。
接口不接收 label、inject_time 或 event_id。
“统一接口”不是宣称端到端联合训练：预测可学习，归因是正常参考下的确定性估计。
现有 audit 在真实正例上离线评估，需要与部署触发后的指标明确分开。

```mermaid
flowchart LR
    A[模块一：多粒度对齐与正常参考] --> B[模块二：双视角编码]
    B --> C[模块三：风险融合预测]
    C --> P[下一分钟故障概率]
    A --> D[模块四：业务条件结构归因]
    P -. 验证阈值触发 .-> D
    D --> R[根因服务排名]
```

模块一/二属于合理的建模与组织；论文主要贡献围绕模块四的等待归属、守恒分解、
结构干预估计展开。修复实现错误本身不是创新点。

## 本轮验证协议

- 预测：两数据集、seed42、5 folds、30 epochs，CPU；参考结束后样本，训练折归一化。
- CPCA：全部 case、first10 fixed、最多100请求/operation/分钟、min20、τ=1。
- 评价：与预测完全相同的正例窗口；所有服务作为候选；缺失窗口/服务按0进入均值；
  无可用正分数为弃权，H@K/RR=0；同分用保守最差名次；主报事件均值，另报窗口。
- 这是修正后可行性验证，不等于三种子最终主表；对照时注明事件集合和评价口径。

## 补充：入口识别与时间戳量化

归因只接受数据集定义的真实业务入口；健康检查和内部 RPC 的独立 Trace 不作入口。
此前 OB 审计混入了 health check，这解释了“单入口却 hard/soft 不同”的现象。
修正入口后 OB hard/soft 必须相同，作为实际数据上的一致性检查。

TT 抽查一个 case：147418 个 HTTP server spans 的开始时间全部落在毫秒边界，
其余 853012 个 spans 中仅 967 个如此。父子边界因此可能有亚毫秒不一致。
严格模式拒绝的请求具有选择性，可能只剩不经过故障路径的简单登录请求；
所以窗口“有分数”不等于根因路径覆盖充足。

提供 `--clock-tolerance-us 1000`：在每条父子边上执行至多 1ms 的有界投影，
平移 child 及其子树，必要时仅在同一误差范围内裁剪 child 时长；入口耗时保持原值。
每条边的误差界不等于深层节点累计位移界；大于该范围的不一致和重叠仍拒绝。
这属于测量量化假设下的适配，不证明真实并行或跨主机偏移都已解决。
严格 0 与 1ms 都必须保留结果；1ms 根据时间戳分辨率设定，不通过测试 H@1 搜索。

正式复现示例（输出必须使用不存在的新路径）：

```bash
.venv/bin/python -B scripts/audit_cpca_gate2.py --dataset tt --cases all \
  --normal-mode first10 --max-requests 100 --restoration excess \
  --gap-policy post --clock-tolerance-us 1000 --output /path/to/new-tt-clock.json
```

每次审计同时导出 cpca / cpca_soft / cpca_replace / cpca_replace_soft，
恢复规则对照使用相同请求与正常参考；不再为每种恢复模式重复读取 ZIP。
