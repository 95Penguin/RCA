# 全局上下文引导的局部证据协同：诊断实验

## 1. 方法

模型保留 LTFP 系统级预测路径，并增加受保护的局部证据协同：

1. LTFP 输出服务局部状态、图传播状态和系统状态；
2. 根因分支从 `detach` 后的服务状态学习局部证据；
3. 系统状态作为 query，对服务证据进行条件化选择；
4. 选择后的证据通过零初始化残差参与系统预测；
5. 系统状态也作为上下文参与根因排序；
6. RCA 损失不能修改 LTFP 主干，故障损失不能修改根因证据空间。

同时将 RCA checkpoint 从 validation-window-MRR 改为与测试一致的 validation-event-MRR。

## 2. 预注册诊断折

- 已知成功折：OB fold 1、TT fold 0；
- 已知失败折：OB fold 4、TT fold 3；
- 30 epochs，seed 42；
- 如果不能修复失败折且保留成功折，则不扩到完整五折。

## 3. 结果

| 数据集/折 | LTFP AP/MRR | 旧 Sidecar AP/MRR | 新协同 AP/MRR |
|---|---:|---:|---:|
| OB-1 | 0.959 / 0.449 | 0.971 / 0.923 | **0.967 / 0.910** |
| OB-4 | 0.953 / 0.792 | 0.967 / 0.592 | **0.964 / 0.322** |
| TT-0 | 0.618 / 0.715 | 0.638 / 0.933 | **0.611 / 0.722** |
| TT-3 | 0.882 / 0.948 | 0.675 / 0.635 | **0.793 / 0.760** |

新模型相对 LTFP 只有 OB-1 同时提高 AP 和 MRR，因此未满足扩展到完整五折的条件。

## 4. 机制诊断

### 可靠性没有学会拒绝证据

四折的平均可靠性分别为：

- OB-1：0.999；
- OB-4：1.000；
- TT-0：0.997；
- TT-3：0.986。

可靠性模块几乎恒等于 1，因此没有发挥“证据不可靠时避免交互”的作用。

### 局部证据缺乏跨事件稳定性

OB fold 4 中，productcatalogservice 有 59 个根因窗口，模型 Top-1 命中为 0；绝大多数窗口都把 recommendationservice 排在第一。错误覆盖 CPU、disk、loss、memory 等不同故障类型。

同一个 productcatalogservice 在 OB fold 1 的 Top-1 命中为 39/48，说明问题不是服务天然不可识别，而是表示对事件配置和故障模式高度敏感。

### 事件级 checkpoint 仍不能解决分布偏移

- OB-4 最佳验证事件 MRR 为 0.783，测试事件 MRR 仅 0.322；
- TT-0、TT-3 的最佳验证事件 MRR 都为 1.000，测试 MRR 分别只有 0.722、0.760。

所以此前的问题不只是窗口级 checkpoint 口径错误。验证事件与测试事件之间仍存在明显分布偏移。

## 5. 结论

全局—局部协同这一研究问题仍有意义，但当前自由学习的 MLP 局部证据不具备跨故障事件稳定性。增加 cross-attention 只能重新加权已有证据，无法修复证据本身。

因此停止扩展该模型，不继续调注意力、门控或残差权重。

下一步如继续粗细粒度路线，应首先把局部证据改为具有明确含义的“相对正常状态偏离”，例如服务条件化正常原型、历史基线残差或反事实恢复证据，再验证这种证据是否能够跨故障类型和跨事件定位同一服务。
