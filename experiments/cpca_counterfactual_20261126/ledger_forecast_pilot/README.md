# CPCA 责任账本加入预测输入：冻结协议试验

目标：验证过去五分钟的服务责任是否提供普通遥测和简单延迟异常之外的预测信息。
这不是已确认的改进。正式排序仍为 median + replace + post + uniform。

## 固定比较

- baseline：原 OCSID，输入、训练算法不变。
- ledger：增加每服务每分钟的 CPCA 责任分和有效证据标记，放入原有 trace 模态。
- simple：增加相同请求集合上的 inclusive mean robust-z 和相同标记，维数与 ledger 一致。
- mask：只增加有效标记，另一列恒零，检查覆盖信息的影响。

复用原训练器：seed42、两个数据集、deployment 五折、30 epochs、原辅助损失，验证 AP 选 epoch、验证 F1 选阈值。第一轮不做结构或超参数搜索。

基线复用核验：OB 完整复跑五折；TT 复跑前两折与冻结结果一致，随后停止重复训练并复用冻结五折输出。
两个数据集的十个冻结 checkpoint 都由当前代码重新推理，逐个测试概率与冻结输出完全一致；据此提取验证概率以设置共同的验证误报预算。TT baseline 日志最后的 KeyboardInterrupt 是主动停止冗余复跑，不是模型训练失败。

## 时间与数据边界

特征生成不读取故障标签、根因标签或 inject_time。读取全部健康/故障分钟，而不是只读取正例 audit。
使用每案例起始十分钟建立健康参考；在参考建立前，新增特征和有效标记均为零。
只有某条 trace 的所有原始 span 均已结束时才纳入该分钟，防止时钟对齐或孤立 span 引入未来数据。
这是比原 audit 的 entry-end 分桶更保守的策略，须报告分桶差异，不能直接冒充原冻结结果。
缺少完整可用账本不删除预测窗口。服务未出现在某 operation 中仍补零，各 operation 等权。
请求计数受每入口每分钟最多 100 个有效请求的预算约束，不可用作全部原始请求覆盖率；完整覆盖原因审计仍是独立待办。
标准化继续只在训练折拟合。健康参考为固定的在线 warm-up 假设，不是跨折学习的统计量。

## 判断标准

优先看五折 AP、验证阈值 F1；同时看 onset 与固定误报预算下的告警/定位。
不要求每折提高，但 ledger 应在总体上显示超过 baseline、simple 和 mask 的增量；否则不继续堆叠结构。
若第一轮值得继续，再扩展三种子验证。初步结果只可称开发性试验。
当前主结构由同批开发数据形成，不能把这轮试验称为独立无选择偏差验证。

所有新增文件及结果先保存在本目录，以保留原仓库已有修改和正式结果。
