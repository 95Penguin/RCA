# 定型与创新性决定

## 最终判断

**保留当前主结构，进入完整论文写作；创新定位应比此前更保守。**
本轮证据支持“有明确适用假设、可复现且有竞争力的服务延迟责任归因方法”，不支持“新的通用因果推断算法”或“端到端联合预测定位网络”。
算法/理论创新较有限，建模与系统设计贡献有一定价值，计算可解释性较强，真实因果解释仍弱。
如果目标要求很强的独立算法创新，当前证据不足；不能承诺录用，也不建议继续无目的的小模块搜索。

这一判断比先前把“无重复计量责任账本”视为潜在强创新更谨慎：ShapleyIQ 和 CRISP 已有嵌套时间分解与影响分析；当前 local 在非叶节点为零，所谓执行/等待分离并没有识别每个服务的真实执行时间。

## 1. 本轮做完了什么

- 对两套数据各 90 个案例的全部 trace/span 做覆盖审计，统计与 capped 定位样本分开。
- 对固定中位数参考做 100 次健康分钟块重采样，保留块内请求、span 和参考键之间的关联。
- 复现全部正式正例窗口及事件排名；OB 分数最大差为 0，TT 最大差为 8.33e-17。
- 完整请求补样、完整请求共享原 cap、无需时间修改请求共享原 cap 三组分层；全部保留原评价窗口，缺证据计零。
- 从已有逐窗分数统一重算 4 个框架与 7 个 specialist，并逐折核对标签、服务轴、面板文件哈希和共同 cohort。
- 修正了“负 logits 被当作弃权”的基线评价问题；另保留简单 z 排序的正异常/有符号控制。
- 在检查现有 ShapleyIQ runner 后，补跑作者核心的对齐输入与 operation 等权控制，而非重写作者算法。
- 增加只用训练事件标签拟合的全局/operation 根因先验，检查服务频率偏置。
- 写出方法章节与近邻贡献对照，证明账本定义性质，并明确时间和因果解释边界。

原 OCSID、CPCA 和历史正式结果没有被改写。所有新评价与文档在本目录，历史文件保留作溯源。

## 2. 定型标准的结果

| 检查 | 结果 | 对方法的决定 |
|---|---|---|
| 健康参考稳定性 | OB 55/55 事件名次始终不变；TT 63/64 始终不变，剩余事件只在 100 次中变化 1 次 | 保留 median 主版本；没有为稳定性增加模型的必要 |
| 全量可识别入口覆盖 | 正例入口 trace 的接受率 OB 99.9766%、TT 92.0772%，不是 capped 样本比例 | 支持有限适用域；不能称任意业务请求均可分析 |
| 完整已记录请求分层 | OB 事件 MRR 不变；TT 0.9922→0.9533，3 个事件排名改变 | partial 处理有实质作用，必须报告，不能宣称完全不敏感 |
| 时间修正依赖 | TT 约 41.58% 的接受 trace 有时间修改；无修改共享 cap 子集事件/窗口 MRR 为 0.9479/0.8661 | 对齐属于方法假设，不能隐去，也不把子集结果称纯时钟因果消融 |
| 强基线 | 有竞争力但不普遍领先；OB LTFP 窗口 MRR 高于 CPCA | 禁止“所有数据集、所有指标最优” |
| 最近邻 ShapleyIQ | TT 合理适配后事件/窗口 MRR=0.9648/0.9534，明显强于旧弱默认 | 最近邻差距缩小，创新不能靠弱对照成立 |
| 预测—定位共享账本 | 前一轮直接拼接在两数据集 AP 都下降 | 不纳入主方法，不继续增加融合结构 |

参考重采样只测试初始化健康期内的抽样变化，不证明跨负载、跨部署或跨健康期漂移的稳定性。
所有开发和选择使用同一批基准数据，事件 bootstrap 也不能被包装成无选择偏差的独立验证。

## 3. 核心排序对照

| 方法 | OB 事件 MRR | OB 窗口 MRR | TT 事件 MRR | TT 窗口 MRR |

| CPCA median + uniform | 0.9198 | 0.8777 | 0.9922 | 0.9640 |
| CPCA edge-only | 0.9062 | 0.8840 | 0.9206 | 0.8998 |
| CPCA caller ownership | 0.3884 | 0.3397 | 0.9680 | 0.9557 |
| LTFP 作者实现适配 | 0.8738 | 0.8867 | 0.9232 | 0.9145 |
| CIRCA 作者实现适配 | 0.8083 | 0.8586 | 0.6713 | 0.5930 |
| 简单 exclusive-mean z（原生汇总） | 0.5790 | 0.4871 | 0.8893 | 0.7651 |
| ShapleyIQ + 健康参考（原生 trace 平均） | 0.3893 | 0.3347 | 0.9036 | 0.9188 |
| ShapleyIQ + 健康参考（operation 等权控制） | 0.3868 | 0.3347 | 0.9648 | 0.9534 |
| 训练事件根因频率先验 | 0.3580 | 0.3957 | 0.4576 | 0.4132 |

各方法信息、参考和原始分数语义不同，表中是统一时间/cohort/服务/并列/缺失口径下的已有适配版本，不是各原论文完整生产系统的完全同环境复现。
operation 先验与全局频率先验在此数据上结果相同；没有证据表明只记住训练根因频率就能解释 CPCA 的成绩。

事件配对结果进一步限定优势：

- OB 相对 LTFP ΔMRR=0.0460，开发数据事件 bootstrap 95% 区间 [-0.0317,0.1258]；窗口分数还略低于 LTFP。
- TT 相对 LTFP ΔMRR=0.0690，区间 [0.0260,0.1198]。
- TT 相对 ShapleyIQ operation 等权控制 ΔMRR=0.02734，区间 [0,0.0625]；3 个事件改善、61 个持平。

同一注入案例可能包含多个事件，因此另外按案例聚类重采样：OB/TT 分别为 51/53 个案例簇。相对 LTFP 的区间约为 [-0.0318,0.1263] / [0.0222,0.1264]；TT 相对 ShapleyIQ 等权控制仍为 [0,0.0625]，结论没有转为显著最近邻优势。

不能将最后一项写成“显著超过最近邻”，也不能以该差距证明强创新。

完整请求分层的一个可核查例子是 `RE2-TT_ts-travel-service_cpu_3`：主样本共 1,091 条请求，其中 173 条包含根因服务 span；只保留完整已记录请求后剩 373 条，其中仅 2 条含根因服务 span。
这解释了该案例的定位证据为何显著减少，但不能据此证明未记录 span 的真实原因。分层改变了可观测请求集合，不是仅改动同一组请求上的数学公式。

## 4. 三类问题的最终归属

### 真正缺少，但当前不应仓促补的机制

- 从 trace 区间区分父服务工作、排队和网络等真实成因：当前观测不足，callee 只是责任规则。
- 任意并行/异步依赖：当前账本限定于可兼容串行模型的入口分量。
- 真实 repair intervention 效果校准：没有这种标签，重放和健康参考不能替代它。

这些限制通过适用域和主张边界处理，不用生成模型或新网络掩盖。

### 已有机制，现已补上关键验证

- 参考采样：本轮显示当前中位数排名非常稳定。
- 请求域与 partial：全量分母及分层已给出；TT 确有敏感性。
- operation 汇总：对 CPCA 有用；强制对其他方法套相同规则未必最优，故同时报告原生与控制。
- callee 归属：OB 强烈有用，TT 仅小幅优于 caller；有排序证据，无物理因果识别证据。

### 必须改正的定义和评价

- 将 local 明确为当前账本的叶节点/残余分量，不能称每个服务自身 CPU 或执行时间。
- 将 gap 称调用外间隙，不能直接称已识别出的网络等待或 callee 因果责任。
- 1ms 是每一步局部对齐预算；子树累积后 TT 个别 span 总位移达 1989μs，超过 1ms 的 span 有 8,533 个。
- “完整”只是全部已记录 span 属于入口可达分量，不保证埋点无未记录 span。
- 一步相邻分钟桶预测不保证完整提前 60 秒；首次事件内真阳性告警也不是系统全局第一次告警。
- 合法负 logits 仍可排序，显式缺失输出才弃权。

## 5. 论文如何写

建议主线保持原任务：**在下一分钟状态预警流程中，提供假设明确、可审计的服务延迟责任诊断。**

贡献可以组织为两项方法/系统贡献和一项实证贡献：

1. 明确 callee 间隙责任与健康参考替换的服务账本，在限定请求域内用入口恢复量统一服务比较。
2. 将预测、告警触发和当前 trace 诊断组织成时间边界清楚的运行流程，分别报告其失败与覆盖。
3. 通过近邻适配、参考重采样、完整请求分层和失败案例，给出可复现的效果及限制。

其中第 1 项是**建模选择及系统实现贡献候选**，不能把守恒等基本恒等式包装成新理论。
预测骨干、operation-aware、反事实、嵌套时间去重均不能单独声称首创。
写作应承认两个数据集上的优势来源不同：OB 主要来自 gap 归属；TT 同时依赖叶节点成本与 gap，且汇总和数据处理影响较大。

可以停止结构搜索，开始完整初稿。若后续确有未参与设计的数据批次，可冻结后做外部验证；没有新数据时不声称已有独立泛化证明。
剩余工作以论文组织、运行成本说明和可核查成功/失败案例为主，不再机械重复确定性 RCA 或追加融合模块。
