# Baseline 接入约定与待完成项

本文件记录接入约定；首批四个框架的实际完成状态、与本计划的具体差异见 [RUNNING.md](RUNNING.md)。其余候选仍待适配。现有历史配置和指标不变。

## 统一问题与可比范围

- 主任务：输入截止 t 的过去 5 个完整分钟，预测精确 t+1 分钟的业务退化状态，包括持续故障；不是“未来一分钟内首次故障”。
- 数据集：RE2-OB、RE2-TT。复用正式业务标签、案例边界和部署组五折：测试组 fold=N，验证组 fold=(N+1)%5，其余训练。
- 分组实现以 `src/data/re2.py` 与 `case_groups.csv` 为准，后续导出显式的 case/window split manifest，所有方法复用同一清单。不能随机拆相互重叠的窗口。
- 原始遥测分辨率可因作者算法而异，但同一预测时刻的数据截止点、5 分钟历史范围、目标和可用原始数据一致。需要更长历史的方法放单独扩展设置，不能暗中多用故障期观测。
- 训练参考统计/词表/归一化/相关图只在训练折拟合。允许作者算法在测试时计算截至 t 的因果窗口统计，但需记录这一机制；不得全测试案例离线拟合。
- 注入时间、注入服务、类型和文件路径是标签/划分元数据，不进入预测输入。故障类型如作为 DiagFusion/TVDiag 的训练任务标签，应显式记录，测试时不可提供真实类型。
- 正常系统标签不证明所有服务局部正常，根因监督只表示归因候选，不把其他异常服务一律标成“无异常”。

## 检测到预测：明确区分三个实验类型

1. **原生未来预测 / 时间目标适配**：输入截至 t，输出 t+1 风险。LTFP 原始 lead-time 目标需改为本项目精确时刻标签；InstantOps 同样核对标签，Maat 还需定义指标异常到业务目标的映射。
2. **历史检测分数预测对照**：按作者算法算出截至 t 可获得的异常分数 a(t)，直接用它对 y(t+1) 排序，名称应说明 score-lag。服务分数聚合到系统分数的规则在训练/验证阶段固定。
3. **作者模型 + 未来分类头**：保留作者模型，在 t 的表示上训练 y(t+1) 分类头，单列 `*-adapted`。这属于任务适配，不能说原始检测算法本身支持未来预测。

AnoFusion/CAD 等若用预测残差评分，t+1 的实际观测不得用于在 t 发出的预测。ART 的故障前后输入窗口也必须按截止点截断。各方法的模式在正式测试前固定；不将 score-lag 与新增分类头的最好结果混作同一个原算法分数。

## 根因任务的时间边界

- 主比较在同一历史截止 t 输出服务排序，目标为 t+1 业务故障的可归因根因候选；只在真实业务正例且有根因标签的窗口评价，不能按每个模型是否报警来挑选评价样本。
- 方法可以在每个可评价截止点运行，由评价器筛选有标签窗口；不得给方法真实根因、未来报警或未来故障起始时间。
- 原算法若必须以当时已知报警为前提，需显式规定截至 t 的公共报警/检测规则并报告覆盖；无法在相同主设置运行时，单列故障后诊断，不把缺结果当 0 分。
- RCD/CIRCA 的正常参考与异常窗口如何定义，必须使用训练数据或截至 t 的可观测规则；不能用未来标签选择“异常段”。
- 指标/操作/实例排名转服务排名时，预先固定聚合、去重、缺失和同分规则。候选服务沿用现有 OB=11、TT=27；不能每个案例只保留被注入服务。
- 窗口级 Hit@1/3/5、MRR 为时间明确的主结果；历史 `root_cause_event_proxy` 属于事后事件聚合，另报并标记，不能把它称为首个预测时刻的定位能力。

## 训练、模型选择与指标

- 不强制所有算法使用相同损失或 epoch；保持作者算法与监督方式，记录训练预算和调参范围。所有调参和阈值选择只使用训练/验证数据。
- 联合框架主表的一组 AP/MRR 必须来自同一个所选模型。后续建议统一采用验证 AP 选择联合模型，平局规则预先写入配置；旧的 validation-loss 或单独 RCA checkpoint 结果保留其原说明，不能混合。
- RCA 专用方法可以按验证 MRR 选自身模型，因为它不报告预测 AP；无监督算法不因加入根因标签而改成监督方法。
- 预测报告连续分数 AP。现有概率模型额外保留 F1@0.5；跨算法比较的 F1 建议增加同一验证集规则选阈值的版本。原始异常分数不强制视为概率，不在其上机械套 0.5。
- 不使用测试集最优阈值或测试标签驱动的 point adjustment。记录测试窗口数、业务正例数、根因覆盖和无法输出的窗口。
- 正式结果按固定五折报告均值与样本标准差；多种子和按案例/事件配对的不确定性分析按统一预算补充。已有反复查看测试结果的研究结果仍是探索性证据。

## 后续输出约定（未实现）

每次运行保留作者原始输出，再导出公共评价文件：

- 身份：method_id、implementation_id、作者源码 commit、适配版本、配置、环境、种子、数据/标签/split manifest 指纹。
- 每个预测：case_id、输入截止时间、目标时间、原始连续风险分数（如支持预测）、有序服务及其分数（如支持 RCA）、可用性/缺失原因。
- 不支持的任务为空并在表中记 `—`，不能生成随机构造的头来补齐输出。
- 预测的不同任务语义、不同源码版本和不同输入规格使用独立运行目录。旧表中的 LTFP 或 adapted 名称保留，不覆盖文件来替换旧结果。
- 产物位置：主工程 `artifacts/baselines/<method_id>/<implementation_id>/<dataset>/<run_id>/`。这是后续目录计划，本次未创建产物。
